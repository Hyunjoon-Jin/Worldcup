# 2026 북중미 월드컵 시뮬레이터 — 개선 계획 기획서

> 작성일: 2026-07-11
> 대상: `hyunjoon-jin/worldcup` (React + TypeScript + Vite + Zustand)
> 목적: 현재 코드베이스를 실제로 점검해 도출한 30가지 이상의 개선 항목을 우선순위·난이도·사용자 체감 변화와 함께 정리한다.

---

## 0. 현황 진단 요약

현재 앱은 조추첨 → 일정 진행 → 조별리그 → 토너먼트 → 확률 대시보드 → 샌드박스까지
핵심 플로우가 잘 동작한다. 다만 실제 코드를 살펴본 결과 다음과 같은 구조적 약점이 있다.

| 구분 | 현재 상태 | 근거 |
| --- | --- | --- |
| 진행 상태 저장 | **저장 안 됨** — 새로고침하면 일정/경기 결과가 전부 초기화 | `useProgressStore`에 `persist` 미적용 (`useDrawStore`·`useSandboxStore`·`useConditionStore`만 적용) |
| 시뮬레이션 성능 | 몬테카를로가 **메인 스레드**에서 동기 실행 | `monteCarlo.ts`의 `runMonteCarloSimulation`이 Web Worker 없이 for-loop |
| 테스트 | **0개** | 저장소 전체에 `*.test.*` / `*.spec.*` 없음 |
| CI | **없음** | `.github/workflows` 부재 |
| 접근성 | 거의 없음 | 전체에서 `aria-*`/`role`이 `MatchDetailModal` 1곳뿐 |
| 능력치 모델 | 랭킹 → 능력치 **선형 변환** | `teams.ts`의 `ratingsFromRank` 단순 1차식 |
| 시뮬레이션 반복 횟수 | 고정값 하드코딩 | `runTeamScenarioSimulation`·`runOpponentForecast`의 `iterations=500` 등 |

아래 개선 항목은 위 약점을 포함해 **8개 영역, 총 34개**로 구성했다.

우선순위 표기: **P0**(즉시/필수) · **P1**(중요) · **P2**(여유 시)
난이도 표기: **S**(작음, ~반나절) · **M**(중간, 1~2일) · **L**(큼, 3일+)

로드맵 1~4차의 핵심 항목을 구현해 반영했다. 각 항목 상태:

C6(시드 재현 조추첨), D4(결승까지 자동 진행), E1(탭/버튼 ARIA), F3(E2E 스모크 테스트).

**2차 현실성 고도화(✅)**: C1(능력치 거듭제곱 곡선 — 상위권 밀집·하위권 격차 확대),
C2(개최국별 홈 이점 세분화 MEX>USA>CAN), C3(승부차기 변동성 반영 — 50:50에 근접),
C4(대회 중 모멘텀 — 최근 성적 기반 폼 가감 + 대시보드 상승세/하락세 표시),
D7(조 난이도 별점 ★1~5), G1(팀 데이터 출처·기준일 명시).

**3차 콘텐츠·몰입·성능(✅)**: D6(대회 통계 대시보드 — 총득점·평균·최다득점차·다득점/무실점 팀),
D5(명장면 피드 — 이변/대승/난타전/승부차기 자동 선별), D1(내 팀 지정 — 팀 페이지 토글 +
대시보드 강조·⭐), G3(대회 규정 인앱 도움말), B5(탭 화면 지연 로딩 — 초기 번들 660KB→208KB).

**실용 변형(🟡)**: B1(몬테카를로) — 완전한 Web Worker 대신 **비동기 청크 실행+진행률+취소**로
UI 멈춤을 해소(사용자 체감 목표 달성). 정식 Worker 이전과 엔진 순수화(H1)는 후속.

**후속 예정(⬜)**: C5(골 타임라인), D2(공유 이미지)·D3(저장 슬롯), E2·E4·E5,
G2, H1·H2, B4, F6·F7 — 별도 PR로 진행.

> 검증: `npm run lint`·`npm test`(36 통과)·`npm run build`·`npm run test:e2e`(핵심 플로우 스모크) 모두 통과.

## A. 데이터 지속성 · 신뢰성

### A1. 진행 상태 영속화 (P0 · M)
- **문제**: `useProgressStore`가 저장되지 않아 새로고침·탭 종료 시 진행한 경기 결과가 모두 사라진다. 사용자가 조별리그 절반을 진행하다 실수로 새로고침하면 처음부터 다시 해야 한다.
- **개선**: Zustand `persist` 미들웨어를 적용하되, `schedule`처럼 파생 가능한 값은 저장에서 제외(`partialize`)하고 복원 시 재생성한다. 저장 키 버전을 두어 스키마 변경 시 안전하게 마이그레이션.
- **체감 변화**: 진행하던 대회가 새로고침 후에도 그대로 이어진다.

### A2. 저장 데이터 버전·마이그레이션 체계 (P1 · S)
- **문제**: 네 개 store의 `persist` 키(`wc2026-*-store`)에 버전(`version`)/마이그레이션이 없어, 데이터 구조가 바뀌면 옛 저장값이 앱을 깨뜨릴 수 있다.
- **개선**: 각 `persist`에 `version`과 `migrate` 지정, 손상 데이터 감지 시 자동 초기화.
- **체감 변화**: 업데이트 후에도 흰 화면/오류 없이 안전하게 실행.

### A3. "이어하기 / 새 대회" 명시적 진입 화면 (P1 · S)
- **문제**: A1 적용 후에는 "저장된 대회"와 "새 대회"를 구분해 시작할 UI가 필요하다.
- **개선**: 앱 진입 시 저장된 진행이 있으면 "이어하기 / 처음부터" 선택 배너 제공.
- **체감 변화**: 이전 대회를 이어갈지 새로 시작할지 스스로 선택.

### A4. 전역 초기화(리셋) 일관성 (P1 · S)
- **문제**: 조추첨 리셋 시 진행/컨디션/샌드박스가 각기 다른 store에 흩어져 있어 초기화 누락 위험이 있다(과거 커밋 이력에서 "조추첨 재시작 시 전체 초기화" 버그 수정 흔적).
- **개선**: `resetTournament()` 단일 액션으로 모든 관련 store를 원자적으로 초기화하는 오케스트레이터 추가.
- **체감 변화**: "새 대회 시작"이 언제나 깨끗하게 초기화.

## B. 성능 · 반응성

### B1. 몬테카를로 Web Worker 이전 (P0 · L)
- **문제**: `runMonteCarloSimulation`이 메인 스레드에서 수천 회 반복 실행돼, 반복 횟수를 올리거나 저사양 기기에서 UI가 순간 멈춘다.
- **개선**: 시뮬레이션 엔진을 Web Worker로 분리하고 결과만 postMessage. 진행률(progress) 콜백으로 프로그레스 바 표시.
- **체감 변화**: 확률 계산 중에도 화면이 부드럽게 반응하고, 반복 횟수를 크게 올려 정확도↑.

### B2. 시뮬레이션 반복 횟수 설정화 (P1 · S)
- **문제**: `iterations`가 곳곳에 하드코딩(500 등). 정확도/속도 트레이드오프를 사용자가 조절 못 한다.
- **개선**: "빠름 / 표준 / 정밀" 3단계 프리셋을 설정에 노출하고 store에서 관리.
- **체감 변화**: 원하는 정확도로 확률을 확인.

### B3. 확률 자동 재계산 디바운스 튜닝·취소 (P1 · S)
- **문제**: `App.tsx`에서 400ms 디바운스로 재계산하지만, 이전 실행을 취소하지 않아 연타 시 계산이 중첩될 수 있다(Worker 이전 시 AbortController로 해결 가능).
- **개선**: 진행 중 계산을 취소하고 최신 상태만 반영.
- **체감 변화**: 능력치를 빠르게 조정해도 최신 결과만 정확히 표시.

### B4. 파생 계산 메모이제이션 (P1 · M)
- **문제**: 순위표·타이브레이커(`rankGroupTeams`)가 렌더마다 재계산될 수 있다.
- **개선**: 입력이 바뀌지 않으면 재사용하도록 selector 메모이제이션/`useMemo` 정리.
- **체감 변화**: 탭 전환·스크롤이 더 매끄러움.

### B5. 코드 스플리팅 · 지연 로딩 (P2 · S)
- **문제**: 모든 탭 컴포넌트가 초기 번들에 포함.
- **개선**: 탭별 `React.lazy` + `Suspense`로 분할, 초기 로딩 시간 단축.
- **체감 변화**: 첫 화면이 더 빨리 뜸.

## C. 시뮬레이션 정교화 (현실성)

### C1. 능력치 모델 고도화 (P1 · M)
- **문제**: `ratingsFromRank`가 랭킹의 단순 1차식이라, 실제 전력차(특히 상위권 밀집·하위권 격차)를 반영 못 한다.
- **개선**: 로지스틱/구간별 곡선으로 변경하고 공격·수비·세트피스 등 세부 지표를 데이터로 분리.
- **체감 변화**: 강팀-약팀 결과가 더 그럴듯해짐.

### C2. 홈 어드밴티지 세분화 (P1 · S)
- **문제**: `HOST_ADVANTAGE = 5`가 개최 3국(미국/멕시코/캐나다)에 일괄 적용된다. 실제로는 경기장 위치·관중에 따라 다르다.
- **개선**: 팀별/경기장별 홈 이점 계수, 중립경기 여부 반영.
- **체감 변화**: 개최국 경기 결과가 더 사실적.

### C3. 무승부/승부차기 모델 개선 (P2 · S)
- **문제**: 승부차기가 `overall + form*0.2 + 50` 강도비의 단순 확률. 실제 승부차기는 변동성이 크다.
- **개선**: 승부차기 전용 능력치(멘탈/키커)·큰 무작위성 반영, 연장 득점 단계 추가.
- **체감 변화**: 토너먼트 승부차기가 더 극적이고 이변 여지↑.

### C4. 대회 중 폼/모멘텀 변화 (P2 · M)
- **문제**: 컨디션(`useConditionStore`)이 대회 시작 시 한 번 고정. 경기 중 부상·연승 모멘텀이 없다.
- **개선**: 경기 결과에 따라 폼이 소폭 오르내리는 모멘텀, 확률적 부상 이벤트.
- **체감 변화**: "상승세 팀", "부상 악재" 같은 서사가 생김.

### C5. 골 상관관계·경기 전개 (P2 · M)
- **문제**: 홈/원정 득점이 독립 포아송이라, 실제의 "한 팀이 몰아치는" 상관을 반영 못 한다.
- **개선**: 이변/난타전 상관 파라미터, 시간대별 득점 타임라인 생성.
- **체감 변화**: 경기 상세가 실제 중계처럼 풍부해짐.

### C6. 결정론적 시드(seed) 재현성 (P1 · S)
- **문제**: `Math.random()` 직접 사용이라 같은 대회를 재현·공유할 수 없다.
- **개선**: 시드 기반 PRNG를 주입해 "이 시드로 다시 돌리기"·공유 가능하게.
- **체감 변화**: 흥미로운 대회를 시드로 저장·공유·재현.

## D. 신규 기능

### D1. "내 팀" 지정 & 맞춤 여정 (P1 · M)
- **문제**: 모든 팀을 균등하게 보여줘, 응원 팀 중심의 몰입 장치가 없다.
- **개선**: 내 팀 지정 시 대시보드/알림/일정이 그 팀 중심으로 강조. 이미 있는 상대 예측(`runOpponentForecast`)을 전면 배치.
- **체감 변화**: 내가 응원하는 팀의 여정에 집중.

### D2. 대회 결과 공유(이미지/링크) (P1 · M)
- **문제**: 완성된 대진표/우승 결과를 외부에 공유할 방법이 없다.
- **개선**: 결과 요약 카드 이미지 생성 + 시드 링크(C6 연계) 공유.
- **체감 변화**: 시뮬 결과를 캡처 없이 바로 공유.

### D3. 저장 슬롯 · 여러 대회 비교 (P2 · M)
- **문제**: 한 번에 한 대회만 진행 가능.
- **개선**: 여러 저장 슬롯, 두 대회 결과 나란히 비교.
- **체감 변화**: "이 조추첨 vs 저 조추첨" 비교 감상.

### D4. 자동 진행(전 경기 시뮬) & 되돌리기 (P1 · S)
- **문제**: 하루/한 타임씩만 진행 가능(`advanceDay`/`advanceTimeSlot`). 끝까지 한 번에 보고 싶을 때 반복 클릭 필요.
- **개선**: "결승까지 자동 진행" 버튼 + 진행 단계 되돌리기(Undo). 조추첨엔 이미 `undoLast`가 있으므로 일정에도 확장.
- **체감 변화**: 결과를 빠르게 보거나, 실수한 진행을 되돌림.

### D5. 이변/명장면 타임라인 피드 (P2 · S)
- **문제**: 이변 기사(`upsetArticle.ts`)가 있으나 대회 전체를 관통하는 하이라이트 피드가 없다.
- **개선**: 대회 종료 후 이변·대량득점·승부차기 명장면을 시간순 피드로.
- **체감 변화**: 대회가 끝나면 "이번 대회 하이라이트"를 한눈에.

### D6. 통계 대시보드(득점왕/최소실점 등) (P2 · M)
- **문제**: 팀 단위 확률은 있으나 대회 통계(최다득점 조, 평균 골 등)가 없다.
- **개선**: 조별/전체 통계 위젯 추가.
- **체감 변화**: 숫자로 대회를 복기.

### D7. 조추첨 결과 난이도 등급 표시 강화 (P2 · S)
- **문제**: `GroupDifficultySummary`가 있으나 "죽음의 조" 같은 직관적 등급이 약하다.
- **개선**: 조별 전력 합/편차로 난이도 뱃지(★~★★★★★) + 내 팀 조 강조.
- **체감 변화**: 어느 조가 빡센지 한눈에.

## E. 접근성 · 반응형 · 국제화

### E1. 접근성(a11y) 전면 보강 (P1 · M)
- **문제**: `aria-*`/`role`이 사실상 모달 1곳뿐. 키보드 내비게이션·스크린리더 지원 미흡.
- **개선**: 탭·버튼·모달에 ARIA 역할/포커스 트랩/키보드 조작 부여, 색 대비 점검.
- **체감 변화**: 키보드만으로도, 보조기기로도 사용 가능.

### E2. 색맹 안전 팔레트 · 명암 대비 (P2 · S)
- **문제**: 진출/탈락/이변 등을 색으로 구분하는데 색각 이상 고려가 없다.
- **개선**: 아이콘/패턴 병행, WCAG AA 대비 확보.
- **체감 변화**: 누구나 상태를 정확히 구분.

### E3. 모바일 레이아웃 정밀화 (P1 · S)
- **문제**: 이미 모바일 뷰가 있으나 대진표(`BracketView`)·순위표의 가로 스크롤 처리 편차.
- **개선**: 넓은 표/대진표를 독립 가로 스크롤 컨테이너로 통일, 터치 타깃 크기 확보.
- **체감 변화**: 휴대폰에서 표가 화면을 밀지 않고 깔끔.

### E4. 다크/라이트 테마 토글 (P2 · S)
- **문제**: 단일 테마.
- **개선**: 시스템 설정 연동 + 수동 토글.
- **체감 변화**: 취향/환경에 맞는 화면.

### E5. 영어(다국어) 지원 (P2 · L)
- **문제**: UI가 한국어 고정. 팀 데이터엔 이미 `nameEn`이 있다.
- **개선**: 문자열 리소스 분리 + 언어 토글.
- **체감 변화**: 해외 사용자도 이용 가능.

## F. 코드 품질 · 테스트 · 배포

### F1. 시뮬레이션 엔진 단위 테스트 (P0 · M)
- **문제**: 테스트가 0개. 타이브레이커·3위 진출·확률 로직은 과거 버그가 반복된 영역(커밋 #5~#14 다수 수정).
- **개선**: Vitest 도입, `tiebreakers`·`qualificationStatus`·`monteCarlo` 핵심 규칙을 골든 케이스로 고정.
- **체감 변화**: 진출 판정 오류 같은 회귀 버그가 사전 차단.

### F2. CI 파이프라인 구축 (P0 · S)
- **문제**: `.github/workflows` 없음. 타입체크/린트/테스트가 수동.
- **개선**: PR마다 `tsc`+`oxlint`+`vitest` 자동 실행하는 GitHub Actions.
- **체감 변화**: 깨진 코드가 병합되지 않음(품질 보장).

### F3. E2E 스모크 테스트 (P1 · M)
- **문제**: 핵심 플로우(조추첨→진행→우승) 자동 검증 없음. `playwright`는 이미 의존성에 있음.
- **개선**: 조추첨 완료 → 결승까지 진행 → 대시보드 렌더 시나리오 1개.
- **체감 변화**: 배포 전 "전체가 돌아가는지" 자동 확인.

### F4. 매직넘버 상수화 · 튜닝 파라미터 중앙화 (P1 · S)
- **문제**: `HOST_ADVANTAGE`, `CONDITION_RANGE`, `UPSET_RATING_GAP`, 득점식 계수(38, 1.25 등)가 여러 파일에 흩어짐.
- **개선**: `engine/config.ts`로 밸런싱 상수 통합, 문서화.
- **체감 변화**: (내부) 밸런스 조정이 쉬워지고 실험 반복 빨라짐.

### F5. 에러 바운더리 · 안전 가드 (P1 · S)
- **문제**: 렌더/계산 예외 시 흰 화면 위험, 손상된 persist 데이터 방어 없음.
- **개선**: React Error Boundary + persist 복원 검증 + 사용자용 복구 안내.
- **체감 변화**: 문제가 나도 앱이 죽지 않고 복구 안내.

### F6. 타입 안전 강화(파생 상태) (P2 · S)
- **문제**: `Record<string, ...>` 다수로 슬롯/조 키가 문자열로 느슨하게 다뤄짐.
- **개선**: 슬롯 ID/그룹 레터를 리터럴 유니온·브랜디드 타입으로 강화.
- **체감 변화**: (내부) 잘못된 키 접근을 컴파일 단계에서 차단.

### F7. 결과 재현용 로깅/디버그 패널 (P2 · S)
- **문제**: 이상한 결과가 나와도 원인 추적이 어렵다.
- **개선**: 개발 모드 디버그 패널(시드·중간 확률·타이브레이커 근거 표시).
- **체감 변화**: (내부) 버그 재현/신고가 쉬워짐.
