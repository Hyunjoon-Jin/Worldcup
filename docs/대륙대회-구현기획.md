# 대륙별 대표 대회 — 구현 기획안

> 근거 문서: `대륙대회-규정조사.md`(본선 포맷) · `대륙대회-예선규정조사.md`(예선) · `대륙대회-일정조사.md`(일정).
> **최우선 설계 원칙: 기존 월드컵 흐름(지역예선→조추첨→본선→커리어 다음 대회)을 절대 꼬이게 하지 않는다.**
> 대륙컵은 **기존 파이프라인을 건드리지 않는 병렬 서브시스템**으로 얹고, 공용 엔진만 "추가(additive)" 방식으로 일반화한다.

---

## 1. 목표와 설계 원칙

**목표:** 6개 대륙 대표 대회(유로·코파·AFCON·아시안컵·골드컵·OFC)를 월드컵과 동급 디테일(예선·조추첨·조별리그·녹아웃·연출·확률·팀 페이지 반영)로 추가.

**설계 원칙 (순서 = 우선순위):**
1. **흐름 불변(flow-safety first).** 월드컵 전용 스토어(`useDrawStore`·`useProgressStore`)와 탭 게이팅 로직은 **읽기 재사용은 하되 스키마·의미를 바꾸지 않는다.** 대륙컵은 별도 스토어·별도 탭.
2. **상태 격리.** 대륙컵 진행 상태는 신규 persist 키로 완전 분리 → 월드컵 저장 데이터와 충돌 불가.
3. **엔진은 additive 일반화.** 공용 함수(조별 시뮬·타이브레이커·브래킷·경기 코어)는 **새 파라미터를 옵션으로 추가**하되 기본값이 기존 동작과 100% 동일하도록 → 회귀 위험 0.
4. **데이터 주도.** 대회별 차이(팀수·조편성·최고3위·3위전·연장·타이브레이커·개최월)는 **하나의 포맷 테이블**로 표현. 코드 분기 최소화.
5. **점진 배포.** 리스크 낮은 순서(독립 실행 → 커리어 타임라인 통합)로 페이즈 분할. 각 페이즈마다 tsc·lint·test·빌드 그린 유지.

## 2. 아키텍처 개요

```
[기존 · 불변]                         [신규 · 병렬]
월드컵 파이프라인                       대륙컵 서브시스템
─────────────                        ─────────────
useQualificationStore (지역예선)        useContinentalStore   (대륙컵 인스턴스 1개: 예선·조추첨·진행)
useDrawStore          (본선 조추첨)      engine/continental/*  (포맷 주도 대회 엔진)
useProgressStore      (본선 진행)        data/continental/*    (6개 대회 포맷·일정·참가국)
useCareerStore        (WC 에디션)   ←→   useSeasonStore        (Phase 2: WC+대륙컵 통합 타임라인)

[공용 · additive 일반화]
engine/generic.ts(조별)·tiebreakers.ts(순위)·drawEngine.ts(조추첨)·matchCore.ts(경기)·bracketTemplate(대진)
  → 기본값 = 기존 동작. 대륙컵은 새 옵션만 사용.
```

**핵심 결정:** 대륙컵 본선 진행을 기존 `useProgressStore`(월드컵 48강 전용, phase idle/group/knockout/complete)에 **얹지 않는다.** 얹으면 "조추첨 안 했는데 다시하기" 같은 스테일 상태 사고가 재현될 위험 → 별도 `useContinentalStore`로 격리.

## 3. 데이터 모델 — `TournamentFormat`

모든 대회를 하나의 선언형 포맷으로 표현(조사 3문서의 수치를 그대로 인코딩).

```ts
// data/continental/formats.ts
export type CupId = 'EURO' | 'COPA' | 'AFCON' | 'ASIAN' | 'GOLD' | 'OFC'

export interface CupFormat {
  id: CupId
  nameKo: string                 // '유럽 축구 선수권' 등
  confeds: Confederation[]       // 참가 연맹(코파=CONMEBOL+CONCACAF초청)
  teams: number                  // 24 / 16 / 8
  groups: number                 // 6 / 4 / 2
  teamsPerGroup: number          // 4
  advancePerGroup: number        // 2
  bestThirds: number             // 4(24팀) | 0
  knockout: KnockoutRoundId[]    // ['R16','QF','SF','FINAL'] | ['QF','SF','FINAL'] | ['SF','FINAL']
  thirdPlace: boolean            // 코파·AFCON·OFC=true, 유로·아시안컵·골드컵=false
  extraTime: 'all' | 'finalOnly' // 코파·골드컵=finalOnly, 그 외=all
  groupTiebreak: 'h2h' | 'overall' // 유로·AFCON·아시안컵=h2h, 코파·골드컵·OFC=overall
  hostAutoQualify: boolean       // 전부 true
  // 일정(대륙대회-일정조사 §2·§4): 개최 월 + 매치데이 오프셋
  schedule: {
    monthWindow: 'summer' | 'january' | 'winterAfcon'  // 개최 시기 유형
    groupDayOffsets: number[]    // [MD1,MD2,MD3] 상대일
    knockoutDayOffsets: Partial<Record<KnockoutRoundId, number>>
    totalDays: number
  }
  // 예선(대륙대회-예선규정조사): 슬롯 배분 + 방식
  qual: {
    directSlots: number
    hostSlots: number
    style: 'groups' | 'combinedWcq' | 'nationsLeague' | 'guestsInvite' | 'prelimSingle'
    matchdays: number            // 예선 캘린더 윈도우 수
  }
}
```

**6개 대회 값(요약 — 조사 문서 확정치):**

| id | teams | groups×perGroup | advance | bestThirds | knockout | 3위전 | ET | 타이브레이커 | 개최월 |
|---|---|---|---|---|---|---|---|---|---|
| EURO | 24 | 6×4 | 2 | 4 | R16·QF·SF·F | ✗ | all | h2h | 여름(짝수 WC+2) |
| COPA | 16 | 4×4 | 2 | 0 | QF·SF·F | ✓ | finalOnly | overall | 여름(짝수 WC+2) |
| AFCON | 24 | 6×4 | 2 | 4 | R16·QF·SF·F | ✓ | all | h2h | 겨울/여름(에디션 데이터) |
| ASIAN | 24 | 6×4 | 2 | 4 | R16·QF·SF·F | ✗ | all | h2h | 1월(WC+1년) |
| GOLD | 16 | 4×4 | 2 | 0 | QF·SF·F | ✗ | finalOnly | overall | 여름(홀수) |
| OFC | 8 | 2×4 | 2 | 0 | SF·F | ✓(에디션) | all | overall | 여름 |

## 4. 엔진 — 재사용 + additive 일반화

| 필요 | 조치 | 회귀 위험 |
|---|---|---|
| 조별리그 시뮬 | `generic.ts` `playSingleGroup`/`snakeSeed` 그대로 | 없음(그대로) |
| 조 순위 | `tiebreakers.ts` `rankGroupTeams(teamIds, matches, opts?)`에 **`opts.mode: 'h2h'|'overall'` 추가**(기본 'h2h' = 현행 유지). overall 모드는 전체 득실 먼저 체인. | 없음(기본값 동일) |
| 최고 3위 선발 | `rankThirdPlaceTeams` 재사용 + **3위 R16 배정 15행 룩업 테이블 신규**(`data/continental/thirdPlaceAllocation.ts`, 유로/AFCON/아시안컵 공용) | 없음(신규 파일) |
| 조추첨/포트 | `drawEngine.ts` `computePots`/`runSeededDraw`를 **N포트·N조 파라미터화**(현행 12조 4포트 기본값 유지) | 낮음(디폴트 보존 필요) |
| 녹아웃 대진 | **`bracketTemplate` 신규 3종**: 24팀(R16 16강, 최고3위 슬롯), 16팀(8강 직행), 8팀(4강). 기존 48/32강 템플릿은 불변. | 없음(신규) |
| 경기(연장·PK) | `matchCore.ts` `simulateKnockoutRaw(..., { extraTime: boolean })` — `false`면 90분 후 즉시 PK. 기본 `true`(현행). | 없음(기본값 동일) |
| 대회 진행 | **신규 `engine/continental/runCup.ts`**: 포맷 받아 조추첨→조별→녹아웃 전 과정 결정론적 시뮬 + 일자별 진행 지원 | 신규 |

**타이브레이커 일반화 상세:** 현행 `rankGroupTeams`는 이미 h2h-first(완결 시). overall 모드는 `chain(byGoalDifference(overall), byGoalsScored(overall), byH2H…)` 순서 체인만 교체. **핵심: 기본 인자 없이 호출하면 현행과 바이트 동일** → 월드컵 경로 무영향.

## 5. 상태 관리 — `useContinentalStore` (신규, 격리)

```ts
// store/useContinentalStore.ts   (persist key: 'wc2026-continental-store' 신규)
interface ContinentalStore {
  activeCupId: CupId | null
  result: CupResult | null        // 예선 결과 + 참가국 확정
  draw: CupDraw | null            // 조추첨(조 편성)
  progress: CupProgress | null    // phase: 'draw'|'group'|'knockout'|'complete', 경기·라운드
  revealed: number                // 일자별 진행 커서(월드컵 revealed와 동일 패턴)
  stageProbabilities: ...         // 대륙컵 진출/우승 확률(온디맨드)
  // actions: selectCup, simulateQual, prepareDraw, advanceDay, advanceToEnd, reset
}
```

- **완전 격리:** 월드컵 스토어를 import하지 않음(랭킹 이월만 `useCareerStore.rankingBase` 읽기 전용 참조).
- **월드컵 진행 로직 패턴 복제**(daily progress·drawPending·stale-field 판정 등 이미 안정화된 UX를 그대로 이식) → 사용자 학습 비용 0, 검증된 흐름 재사용.
- **한 번에 하나의 대륙컵만 활성**(activeCupId). 대회 전환은 명시적 초기화 → 스테일 상태 사고 원천 차단.

## 6. UI / 흐름 설계 (인터페이스 개편)

### 6-1. 신규 탭 "🏆 대륙컵" (단일 허브)
탭을 6개 늘리지 않는다. **하나의 "대륙컵" 탭 안에서 대회 선택 → 그 대회의 예선/조추첨/조별/녹아웃/우승을 내부 서브네비**로 진행. 월드컵 화면 컴포넌트(조 순위표·브래킷·일자별 진행·조추첨 연출)를 **포맷 파라미터로 재사용**.

```
[대륙컵 탭]
 ├─ 대회 선택 그리드 (유로·코파·AFCON·아시안컵·골드컵·OFC 카드 — 개최 시기·참가국·현재 챔피언)
 └─ 대회 진입 시 내부 서브탭: [예선] [조추첨] [일정 진행] [조별] [녹아웃] [확률]
      → 월드컵 탭들과 동일한 UX·컴포넌트, 데이터만 대륙컵 인스턴스
```

### 6-2. 기존 탭 확장(스키마 불변, 표시만 추가)
- **내 팀:** 대륙컵 예선/본선 일정·성적·확률 섹션 추가(팀의 소속 연맹 대회).
- **FIFA 랭킹:** 대륙컵 경기 결과가 이미 랭킹에 반영되므로(§8) 별도 UI 변경 최소.

### 6-3. (선택·Phase 2) 상위 개편 — "대회 허브/시즌 캘린더"를 홈으로
탭 바가 커지는 문제를 근본 해결하려면, **최상위에 '시즌' 랜딩**을 두고 그 아래 월드컵·대륙컵을 카드로 배치하는 개편이 이상적. 단 이는 기존 진입 흐름을 바꾸므로 **Phase 2에서 타임라인 통합과 함께** 도입(그 전까지는 6-1의 단일 탭 추가만으로 무리 없이 동작).

**흐름 안전장치:** 대륙컵 탭은 월드컵 탭 게이팅(`tabDisabled`)과 **독립**. 대륙컵 미진행 시에도 항상 접근 가능(내부에서 "대회 선택"부터 안내). 월드컵 진행 중에도 대륙컵을 병행 조회 가능(상태 격리로 상호 간섭 없음).

## 7. 커리어 타임라인 통합 (Phase 2)

현재 커리어는 WC 에디션 단위(`useCareerStore.editionIndex/year`)로만 전진. 대륙컵을 **연도 캘린더에 끼워** 연속 흐름으로 만든다.

- **신규 `useSeasonStore`:** `currentDate`(연-월)를 축으로, `대륙대회-일정조사 §1` 배치 규칙(WC=짝수, 유로+코파=WC+2 짝수, 아시안컵=WC+1 1월, 골드컵=홀수, AFCON=2년, OFC)으로 **다가오는 대회 큐**를 생성.
- **"다음 대회로 진행"**이 WC 뿐 아니라 그 사이 대륙컵도 순서대로 제시 → 사용자는 타임라인을 따라 WC→(대륙컵들)→WC를 관전.
- 각 대회 종료 시 성적을 `carriedForm`·`rankingBase`에 반영(§8).
- **안전장치:** Phase 1(독립 실행)에서 대륙컵 엔진·UI를 완성·검증한 뒤에만 타임라인을 얹는다. 타임라인은 기존 `advanceToNextEdition`을 대체하지 않고 **감싸는(wrapper)** 형태 → WC 단독 흐름은 그대로 유지.

## 8. FIFA 랭킹 · 커리어 폼 반영

- **이미 준비됨:** `ranking.ts`에 `continentalGroup=35`·`continentalKnockout=40` 중요도 계수 정의. 예선은 `qualifier=25`.
- 대륙컵 경기 결과를 `applyMatchElo`로 랭킹에 누적(본선=대륙 계수, 예선=25). 라이브 랭킹 훅(`useLiveFifaRanking`)에 대륙컵 played 경기를 friendlies처럼 추가 반영.
- 우승/성적을 `finalsFormDeltas` 유사 로직으로 커리어 폼에 소폭 반영 → 대회 간 연속성.
- 월별 랭킹 스냅샷(`useRankHistoryStore`)에 대륙컵 기간도 기록.

## 8′. 필수 통합 요구사항 (사용자 확정 — 전 페이즈 관통 제약)

아래 5개는 "있으면 좋은 것"이 아니라 **모든 페이즈가 반드시 지켜야 하는 불변 제약**이다.

### (1) 일정 충돌 절대 방지 — 단일 마스터 캘린더
**요구:** 대륙컵 예/본선 경기가 월드컵 지역예선 등 다른 경기와 **같은 날짜에 겹치면 안 되고**, 중첩으로 인한 오류가 나서도 안 된다.

**설계:**
- **단일 마스터 캘린더(`engine/season/masterCalendar.ts`)** 를 진실의 원천으로 둔다. 월드컵 예선·월드컵 본선·6개 대륙컵 예/본선·친선을 **모두 이 한 곳에서 FIFA 매치 창(일정조사 §0)에 배치**한다.
- **불변식(invariant): 한 팀은 한 날짜에 최대 1경기.** 캘린더 빌드 시 팀별 날짜 점유(occupancy) 맵을 만들어, 경기를 넣기 전 **충돌 검사 → 충돌 시 같은 창 내 다른 슬롯/날짜로 자동 배치**. 배치 불가면 그 경기는 그 창에서 제외(로그).
- **친선 배정 일반화(중요):** 현행 친선전은 "그날 WC 예선이 있는 팀"만 제외한다. 이를 **"그날 어떤 대회든(WC 예선/본선·대륙컵 예/본선) 경기가 있는 팀"을 모두 제외**하도록 확장 → 대륙컵 참가팀이 친선까지 잡혀 이중 배정되는 사고 원천 차단.
- **현실 근거:** 일정조사 §1대로 실제로도 대회들은 시기가 어긋나므로(예선은 창별, 본선은 특정 여름/겨울), 마스터 캘린더는 이 배치를 그대로 재현하면 자연히 무충돌. 시뮬 단순화 모델(라운드=윈도우)도 **연맹별 창을 겹치지 않게 배정**하면 유지 가능.
- **회귀 안전:** 마스터 캘린더는 월드컵만 있을 때 **현행 `buildQualCalendar` 결과와 동일**해야 한다(대륙컵 미활성 시 바이트 동일). 대륙컵이 활성일 때만 추가 경기를 무충돌로 끼운다.
- **검증:** "임의의 (팀, 날짜) 쌍에 경기 ≤ 1" 을 **불변식 테스트**로 못박는다(전 대회·전 시즌 전수 검사).

### (2) 팀 정보 전 영역 — 월드컵과 동일 층위 통합
**요구:** 팀별 경기일정 등 **모든 팀 정보 영역**에서 대륙컵 예/본선을 월드컵과 **같은 층위**로 함께 표시.

**설계:**
- **팀 경기 집계기(`engine/season/teamFixtures.ts`)**: 한 팀의 (WC 예선·WC 본선·대륙컵 예선·대륙컵 본선·친선) 경기를 **하나의 통합 일정 리스트**로 병합(대회 태그 + 날짜순). 최근 경기·예정 경기·성적을 대회 구분 배지와 함께 단일 타임라인으로.
- `MyTeamTab`·`TeamDetailPage`·`TeamQualificationSection`이 이 집계기를 참조 → **월드컵 전용이던 섹션을 "대회 무관 통합" 섹션으로 승격**(월드컵도 이 통합 경로로 표시되도록 리팩터, 단 표시 결과는 기존과 동일 유지).

### (3) FIFA 랭킹 — 대륙컵 빠짐없이 반영
**요구:** 대륙컵(예선·본선)을 랭킹에 **누락 없이** 반영.

**설계:**
- 모든 대륙컵 경기를 `applyMatchElo`로 반영: 본선 조별 `continentalGroup=35`·녹아웃 `continentalKnockout=40`, 예선 `qualifier=25`(모두 기존 정의됨).
- `computeLiveRanking`에 **대륙컵 played 경기 인자를 추가**(friendlies와 동형) → 라이브 랭킹·월별 스냅샷·팀 페이지 순위가 대륙컵까지 포함해 단일 계산.
- **누락 방지 검증:** "랭킹에 반영된 경기 집합 = 마스터 캘린더의 played 경기 집합" 을 테스트로 확인.

### (4) 역대 성적 아카이빙 — 팀별 열람
**요구:** 대륙컵 역대 성적도 월드컵처럼 아카이빙해 팀별로 조회.

**설계:**
- `useHistoryStore`(현 월드컵 에디션 스냅샷)를 **대회 종류 필드(competition: 'WC'|CupId)로 확장**하거나 병렬 `useContinentalHistoryStore` 추가. 각 대륙컵 종료 시 `buildEditionSnapshot` 유사 스냅샷(우승·성적·참가국·종료 시 랭킹) 축적.
- 팀 상세 "역대 기록"에 **대회별 통산 성적**(월드컵/유로/코파/… 우승·최고 성적·통산 전적) 섹션 추가. 월드컵과 동일 카드 UI 재사용.

### (5) 확률 3종 — 월드컵과 동일 계산
**요구:** 대륙컵 **본선 진출 확률·다음 스테이지 진출 확률·우승 확률**을 월드컵처럼 계산·표시.

**설계:**
- **예선 단계 확률:** `engine/qualification/probability.ts`(몬테카를로, stageProbabilities) 패턴을 대륙컵 예선에 재사용 → 대륙컵 본선 진출 확률 + 차수별 진출 확률.
- **본선 단계 확률:** `simCore`/`monteCarlo`/`projectedFinals` 패턴 재사용 → 대륙컵 조별 통과·라운드별 진출·우승 확률(포맷별 브래킷 반영).
- 팀 페이지·확률 대시보드에 월드컵과 동일한 진출 체인 그래프로 표시. **조추첨 전에는 `projectedFinals`류 무작위 조편성 기대값**으로 예상 상대·라운드 확률 제공(월드컵과 동일 UX).

**Phase A′ — 마스터 캘린더 (§8′-(1), 충돌 방지 토대)**

**Phase B — 대륙컵 본선(독립 실행) UI**

- 월드컵 컴포넌트 재사용(조 순위표·브래킷·조추첨 연출·PK 스코어). 최고3위·3위전·연장 규칙 대회별 정확 반영.

- 예선 일자별 진행 + **본선 진출·차수별 진출 확률(§8′-(5))** + 마스터 캘린더 편입(무충돌).

**Phase D — 팀 정보·랭킹·아카이브 통합 (§8′-(2)(3)(4))**
- **통합 경기 집계기**(`teamFixtures.ts`)로 내 팀/팀 상세/예선 섹션이 WC+대륙컵을 **동일 층위 단일 타임라인**으로 표시.
- 대륙컵 경기 **FIFA 랭킹·월별 스냅샷 누락 없이 반영**(반영 집합 = 캘린더 played 검증).
- **역대 성적 아카이빙**: 대회별 통산 성적 스냅샷 + 팀 상세 "역대 기록" 대회별 섹션.

**Phase E — 커리어 타임라인 통합 (선택·최상위 개편)**

- 성적의 커리어 폼·랭킹 이월 연속화.

### E. UX / 정보구조 (IA)
- **단일 "대륙컵" 허브 탭(기획 §6-1) 기각.** 6 scoped 탭 × 7 대회 + 2 글로벌 = **44 탭**은 파탄. 허브 탭은 6개 대회를 영구히 WC 하위로 종속 + 최대 4~5단 중첩.
- **권장: 하이브리드(홈 + 컨텍스트 스위처 + 글로벌 레일).**
  - **Tier 1 글로벌 레일(약 4개):** `🏠 홈(시즌/캘린더)` · `⭐ 내 팀` · `🌐 FIFA 랭킹` · `📜 기록/명예`.
  - **Tier 2 대회 워크스페이스:** 대회 선택 시 **컨텍스트 헤더(대회명·엠블럼·색상 + 스위처 칩)** + 기존 6개 stage 탭을 **`competitionId`로 스코프**. 탭 수는 대회 수와 무관하게 고정.
- **핵심 완화 사실:** 한 국가는 **정확히 한 연맹 소속** → 팀 페이지는 **월드컵 + 그 팀의 대륙컵, 최대 2개**로 붕괴. 팀 페이지는 **3분할 세그먼트 컨트롤 `[전체·월드컵·대륙컵]`**, 기본은 **대회 배지 붙은 통합 시계열 타임라인**(무슨 대회인지 몰라도 "다음 경기"가 보임).
- **FIFA 랭킹은 글로벌 유지**(스코프 대상 아님), 대륙컵 결과만 먹임.
- **마이그레이션: 셸 우선(shell-first).** Phase B에서 **WC를 "대회 #1"로** 등록하는 `competitionId` 서술자 + 홈/스위처/세그먼트 레이아웃만 도입(스토어 수술 0, 동작 불변). 스토어를 `competitionId`로 네임스페이스하는 무거운 작업은 이후 페이즈.

## 13. 감사 반영 — 수정된 아키텍처 결정 & 페이즈 재정비

**바뀐 핵심 결정 5가지:**
1. **"additive 옵션" → "포맷 서술자 기반 파라미터화 + 병렬 제네릭 시뮬레이터".** drawEngine·bracket·simCore는 48강 하드코딩이라 신규 코드가 상당함. 공용은 `matchCore`+`tiebreakers`+`progressBracket`만.
2. **절대 날짜축을 최우선 선행.** 모든 fixture에 ISO `date` 부여 + 본선 스케줄 연도 파라미터화 + "대륙컵=∅ 바이트 동일" 골든 테스트. 이게 없으면 충돌 불변식 자체가 성립 불가.
3. **개최국·전력은 전역 금지, 명시 인자 주입.** 대륙컵은 `hostIds`·오프셋을 인자로만. 전역 `setCurrentHosts`/`getRatings`/`buildSnapshot` 미사용. (부수적으로 simWorker 개최국 버그도 수정.)
4. **역대기록·확률은 병렬 신설.** `useContinentalHistoryStore` + 제네릭 시뮬 위 대륙컵 확률 누산기. 랭킹은 `applyContinentalElo` + 캐시 키 확장 + 불변식 테스트.
5. **UX는 셸 우선 하이브리드.** 홈+스위처+글로벌 레일, 팀 페이지 3세그먼트 타임라인. WC를 대회 #1로 등록해 동작 불변 상태에서 IA만 전환.

**재정비된 페이즈 (선행 de-risk 추가):**

| 페이즈 | 내용 | 회귀 게이트 |
|---|---|---|
| **Phase 0 — 토대 리팩터(신규·행동 불변)** | ① 전 fixture ISO `date` 필드 + 본선 스케줄 연도 파라미터화 ② `hostIds` 전(全) sim/draw 명시 주입(전역 의존 제거) + simWorker 버그 수정 ③ `competitionId` 서술자(WC=대회#1) 셸 도입 ④ 골든 테스트(현행 캘린더·친선·랭킹 바이트 동일) | **모든 산출물 행동 불변**, 202+골든 그린 |
| **Phase A — 데이터·엔진 일반화** | 6개 `CupFormat`+15행 배정표 / drawEngine·bracket(24·16·8)·tiebreaker(mode)·simCore(제네릭) 파라미터화 / ET 처리 결정(B3) / `runCup.ts` + 단위 테스트 | 인자 없는 호출 바이트 동일 |
| **Phase A′ — 마스터 캘린더** | 전 대회 무충돌 배치 + **"(팀,날짜)≤1" 불변식 전수 테스트** + 친선 date축 재작성(∅시 시드 환원) | 대륙컵=∅ 시 현행과 바이트 동일 |
| **Phase B — 대륙컵 본선(독립) + UX 셸** | `useContinentalStore` + 홈/스위처/글로벌 레일/팀 3세그먼트(WC만 등록) + 대륙컵 조추첨→조별→녹아웃→우승 + 본선 확률 | WC 동작 불변 |
| **Phase C — 대륙컵 예선** | 대회별 예선(아시안컵=AFC WCQ 2R 재사용 등) + 예선 확률 + 마스터 캘린더 편입 | 무충돌 유지 |
| **Phase D — 통합(팀·랭킹·아카이브)** | 통합 경기 집계기 + `applyContinentalElo`(반영=played 불변식) + `useContinentalHistoryStore` + 팀 페이지 2번째 세그먼트 자동 등장 | 랭킹 누락 0 테스트 |
| **Phase E — 커리어 타임라인** | `useSeasonStore` 연속 캘린더 + 대회 큐 + 성적 이월 연속화 | WC 단독 흐름 보존 |

**최우선 선행:** **Phase 0**. 절대 날짜축·hostIds 주입·competitionId 셸은 이후 모든 페이즈의 전제이자, 지금 당장 착수해도 **행동이 바뀌지 않아 회귀 위험이 0**이며 기존 잠재 버그(본선 연도 미시프트·simWorker 개최국)까지 함께 잡는다.

> 승인해 주시면 **Phase 0**부터 착수한다(행동 불변 토대). 또는 유로 1개 **세로 슬라이스**로 Phase 0~B를 관통해 눈으로 확인한 뒤 확장하는 방식도 가능.
