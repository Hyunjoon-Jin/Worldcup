# 고도화 계획 v2 — 차세대 목표 50선

> 작성일: 2026-07-12
> 대상: `hyunjoon-jin/worldcup`
> 전제: v1 로드맵(안정화·현실성·몰입·저장·테마 등 31개)은 이미 `main`에 반영 완료.
> 이 문서는 그 위에서 **앱의 성격 자체를 확장하는** 완전히 새로운 고도화 목표를 다룬다.

## 이 계획의 방향성

현재 앱은 "혼자 돌려보는 프론트엔드 시뮬레이터"다. v2의 큰 그림은 세 축으로 도약한다:

1. **깊이(Depth)** — 팀 단위 → **선수·전술 단위** 시뮬레이션
2. **지능(Intelligence)** — 템플릿 → **LLM 기반 생성·질의응답**
3. **연결(Connectivity)** — 로컬 저장 → **백엔드·소셜·공유**

표기: 우선순위 **P0/P1/P2** · 난이도 **S/M/L** · 의존성 🗄 백엔드(Supabase) · 🤖 LLM(Claude API) · ☁ 배포(Vercel/Netlify)

## ✅ 확정: 백엔드 미도입 (2026-07-12)

서버(계정·DB·서버 경유 API)를 도입하지 않기로 결정했다. 따라서 다음은 **범위에서 제외**한다:

- **C 전체(11~15)** — 클라우드 저장·인증·갤러리·리더보드
- **B(6~10)** — 서버 경유가 안전한 LLM 기능(키 보안상 프론트 직접 호출 부적합)
- **D 중 서버 필요(17 공동관전·18 투표·20 댓글)**, **I44 모니터링**

**대신 집중하는 순수 프론트엔드 트랙(약 35개)**: A(선수·전술 심화), E(번들 데이터 기반 실제
랭킹·조추첨·역대 비교), F(고급 분석), G(시각화), H(접근성·i18n), I(PWA·Worker·배포·SEO),
J(리텐션). D16(브래킷 챌린지)·D19(결과 이미지)는 **URL 인코딩/캔버스로 서버 없이** 구현한다.

**재정렬된 릴리스:** R1(Quick Win + 시각화/분석) → R2(PWA·Worker·i18n) → R3(선수·전술 심화) → R4(데이터·리텐션).

## 핵심 기술 결정 (선행 판단 필요)

이 50개는 몇 가지 **아키텍처 갈림길**에 걸려 있어, 먼저 정해야 뒤가 풀린다.

1. **백엔드 도입 여부** — C·D·E·J의 절반이 서버를 전제한다. Supabase(Auth+DB+Storage) 연동을
   결정하면 11~20, 47 등이 한 번에 열린다. 현재 세션에 Supabase MCP가 연결돼 있어 실현 가능.
2. **LLM 통합 방식** — B 전체가 Claude API 의존. 키를 프론트에 두면 안 되므로 백엔드(엣지 함수)
   경유가 필요 → #1 결정과 묶인다.
3. **선수 데이터 확보** — A·#24는 방대한 스쿼드 데이터가 필요. 데이터 소스/갱신 전략이 선결.
4. **엔진 순수화(H1 재소환)** — #42(정식 Worker)·#28(What-if)·#3(전술)은 v1에서 미룬
   "엔진을 store에서 분리" 리팩터링이 전제. 여기서 갚아야 할 기술부채.
